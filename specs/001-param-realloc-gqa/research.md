## R1. 参数量解析模型

### 公式推导

结构：词表 `V=2048`，上下文 `C=256`，宽度 `d`，层数 `L`，注意力头数 `h`，
KV 头数 `k`，MLP 隐藏维 `f`，embedding 与输出投影共享权重。

| 组件 | 参数量 |
|---|---|
| token embedding（与 head 共享） | `V·d` |
| 位置编码 | `C·d` |
| 最终 LayerNorm | `2d` |
| 每层 · 注意力（MHA，`k=h`） | `4d² + 4d` |
| 每层 · 注意力（GQA/MQA，`k<h`） | `2d² + 2d + 2k·d²/h + 2k·d/h` |
| 每层 · MLP（GELU，`f=4d`） | `8d² + 5d` |
| 每层 · LayerNorm ×2 | `4d` |

合计：`Total = V·d + C·d + 2d + L·(attn + mlp + 4d)`
即 `Total = 2306d + L·(attn + mlp + 4d)`

### 验证

基线 `d=128, L=4, h=4, MHA, f=4d`：

```
embedding + pos + final LN = 262,144 + 32,768 + 256 = 295,168
每层 = (4·128² + 4·128) + (8·128² + 5·128) + 4·128
     = 66,048 + 131,712 + 512 = 198,272
Total = 295,168 + 4 × 198,272 = 1,088,256
```

**与实测 1,088,256 完全一致**，公式可信。

### 计算量模型（用于预算核对）

每 token 乘加数（MACs）按三部分计，`T = 256`：

```
projections + MLP = L · (attn_proj + 8d²)
attention core    = L · 2·T·d            （QKᵀ 与 AV）
```

其中 `attn_proj = 2d² + 2d²·(kv_heads/h)`：MHA 时退化为 `4d²`，MQA（`kv_heads = 1`）时为 `2d² + 2d²/h`。
偏差项（每层约 `4d`）忽略不计。

**⚠️ 修正记录**：注意力核项 `2·T·d` 随层数**线性增长**，不可省略。本表早期版本仅计入
`projections + MLP`，因而把 C3 的代价低估为 +0.5%；计入注意力核后实际为 **+8.2%**。
紧随其后的表格已按完整模型修正。此外须注意：本项目用 `repeat_interleave` 把 k/v 扩展回
查询头数，**只压缩了 KV 投影**，注意力核仍按 `h` 个头计算——真正融合的 MQA 核会额外压缩核项。

| **C3** | 112 | 6 | MQA | **1,056,272** | **−2.94%** | 790,272 | 344,064 | **1,134,336** | **+8.18%** |

预算校验：5× 基线 ≈ **5,242,880** MACs/token。全部候选均在 1.25× 以内，打分时间预算宽裕。

### C3 为什么是主候选

```
C3: d=112, L=6, MQA
  embedding + pos + final LN = 229,376 + 28,672 + 224 = 258,272
  每层 = (2·112² + 2·112 + 2·112²/4 + 2·112/4) + (8·112² + 5·112) + 4·112
       = (25,088 + 224 + 6,272 + 56) + (100,352 + 560) + 448
       = 31,640 + 100,912 + 448 = 133,000
  Total = 258,272 + 6 × 133,000 = 1,056,272
```

**C3 的三个关键性质**：

1. **参数量与基线几乎相同**（−2.94%，在 ±3% 内）→ 排除"单纯变大"的解释。
2. **计算量为 +8.18%**（含注意力核项；仅计投影与 MLP 时为 +0.5%）→ 该增幅远低于 5× 预算
   （上限 ≈ 5,242,880 MACs/token），打分时间预算自动满足；但**不能**声称"计算量持平"。
3. **层数多 50%**（6 vs 4）→ 直接攻击诊断出的"层数过浅"短板。

达成方式：MQA 每层省下 `50,624 − 31,640 = 18,984` 个参数，6 层共省 **113,904**；
这正是把预算从 KV 投影搬到深度的来源。

- **Decision**: 主候选为 C3（`d=112, L=6, MQA`）。
- **Rationale**: 唯一同时满足"参数量持平（−2.94%，在 ±3% 内）+ 计算量受控（+8.18%，远低于
  5× 上限）+ 层数显著增加（+50%）"的配置。
- **Alternatives considered**: C2 (+6.84%) 与 C4 (+7.53%) 都超出 ±3% 预算带；
  C1 (−9.10%) 与 C5 (−7.71%) 参数偏少，需在筛选后判断是否为"变小"所致；
  C6 (−4.47%) 作为轻度变体保留，用于检验宽度收窄是否带来损失。

## R3. 无法等价匹配的参数约束（重要）

**结论：不存在同时改变注意力类型与层数、且参数量严格相等的配置。**

原因：注意力与 MLP 是每层唯一的两块参数来源。要增加一层就必须省出
`attn + mlp + 4d` 的量级（约 13 万参数），而 KV 共享单层只能省下
`2d²(1 − k/h) + 2d(1 − k/h)`（`d=112, h=4, k=1` 时为 18,984）。因此必须同时收窄宽度
才能回到预算带内，而收窄宽度本身是第二个变量。

处理方式（诚实设计，而非掩盖）：

- **主对比（公平性最强）**：C3 (1,056,272) vs BASE (1,088,256)，参数差 −2.94%，
  每 token MACs 差 +8.18%（1,134,336 vs 1,048,576）。这是"同 token、近似同参数、计算量受控"的
  对照，满足 spec 的 SC-002。**不可描述为"同计算量"**——+8.18% 虽远低于 5× 上限，但它是真实差异。
- **消融（隔离 KV 共享）**：C3 vs C4（`d=112, L=6` 不变，仅 MHA ↔ MQA），
  参数差 +10.8%（C4 更多）。**若 C3 以更少参数胜出，说明 KV 共享确实有益；
  若 C4 胜出，则提升来自层数而非 KV 共享——此时主机制陈述必须改写**，
  MQA 降级为"省参数的工程手段"而非"提升 BPB 的机制"。
- **消融（隔离层数）**：C1 vs BASE（`d=128, L=4` 不变，仅 MHA ↔ MQA），
  以及 C1 vs C3（同为 MQA，层数与宽度同时变化，仅作趋势参考）。

- **Decision**: 采用上述三段式对比，并将参数/计算量差异全部显式披露。
- **Rationale**: 强行宣称"参数严格匹配"会构成误导。披露差异并给出可推翻的判据，
  比追求表面整洁更有科学价值。
- **Alternatives considered**: 通过缩小 MLP 隐藏维凑平参数——会引入第三个变量
  （MLP 容量），使机制归因更模糊，故拒绝。

## R4. 噪声底估计（判断差异是否真实）

**问题**: 单 seed 的 BPB 差异可能是随机性，而非方法效果。

**方案**: 在筛选前先测噪声底——基线跑 3 个 seed（17 / 42 / 123），
候选胜者也跑 3 个 seed，以标准差 σ 作为"差异是否显著"的门槛。

**判据**: 只有当候选与基线的均值差 > 2σ 时，才认为存在真实信号。

- **Decision**: 建立噪声底后再做选择性结论；单 seed 差异一律不作结论。
- **Rationale**: GPU 吞吐下（1200 步约 23 秒 + 加载约 20 秒），多 seed 的成本极低，
  没有理由不测。
- **Alternatives considered**: 直接引用文献中的经验方差——不同模型规模下不适用。

## R5. 筛选协议：全协议筛选而非缩短训练

**关键判断**: 由于 GPU 训练吞吐约为 CPU 4 线程的 29 倍，**完整 1200 步协议仅需约 23 秒**，
单次运行总成本约 43 秒（含约 20 秒数据加载）。

因此**不采用"缩短步数快速筛选"**：

| 方案 | 成本 | 风险 |
|---|---|---|
| 缩短训练筛选（约 300 步） | 更低（约 30 秒/次） | **排名可能不可迁移**（spec 边界情况 #1） |
| **全协议筛选（1200 步）** | 约 43 秒/次 | 无——与最终评估口径完全一致 |

- **Decision**: 全部筛选候选均跑完整 1200 步 / 9,830,400 目标的协议。
- **Rationale**: 在成本几乎相同的前提下彻底消除"短训练排名不可迁移"风险，
  这是本次算力条件下才能做的奢侈选择，也是 spec 边界情况 #1 的直接消解。
- **Alternatives considered**: 缩短训练筛选——收益仅为每次省约 13 秒，
  代价是结论可靠性下降，不值得。

## R6. 训练精度：bf16 vs fp32

**问题**: GPU 上 `--precision auto` 会选择 bf16。bf16 仅 8 位尾数，
对 1M 参数级别的小模型可能损失精度。但 3060 的 fp32 吞吐明显低于 bf16。

**方案**: 将训练精度作为筛选变量之一，在 C3 上同时跑 bf16 与 fp32 各 1 次，
比较验证 BPB。若 fp32 明显更好且时间可接受，则最终模型用 fp32 训练。

**注意**: `train.py` 的验证打分硬编码为 fp32（[train.py:66](../../code/train.py)），
因此无论训练精度如何，验证 BPB 都在 fp32 下计算，这一点已核实。

- **Decision**: 待测。作为筛选阶段的一个受控变量。
- **Rationale**: 未经验证就接受 bf16 属于"假设合规"，违反宪法第 VII 条精神。
- **Alternatives considered**: 强制全部 fp32 训练——可能不必要地牺牲吞吐，故先测。

## R8. 噪声底实测（阶段 A 结果，2026-09-19）

**测量条件**：`configs/base.json`（= 基线结构，`kv_heads=4`），`--implementation student`，
GPU（RTX 3060）+ bf16 训练，seed 17 / 42 / 123，各 1200 步 = 9,830,400 targets。
验证集打分由 `train.py` 硬编码为 **fp32**（[train.py:74](../../code/train.py)），故 BPB 本身
不受训练精度影响。

| seed | 验证 BPB |
|---:|---:|
| 17 | 2.072792 |
| 42 | 2.075514 |
| 123 | 2.077814 |

| 统计量 | 值 |
|---|---:|
| 均值 | **2.075373** |
| 标准差（n−1） | **0.002514** |
| 极差 | 0.005022 |
| **2σ 判据门槛** | **0.005028** |

**判据（T011 输出）**：候选胜出需满足

```
mean(candidate) < 2.075373 − 0.005000
```

即候选与基线均值差必须**超过 0.0050 BPB** 才算真实信号。相对量为 **0.24%**。
本门槛取 `max(σ_3seed, 基线已知波动)`：n=3 的标准差估计效力偏弱，但极差（0.005022）
与 2σ（0.005028）高度一致，说明该估计稳定，无需上调。

### 与 CPU/fp32 基线的交叉核对

| 对照 | 值 | 差异 |
|---|---:|---:|
| CPU + fp32，seed 17（`runs/baseline/`） | 2.071083 | — |
| GPU + bf16，seed 17 | 2.072792 | **+0.001709** |
| GPU + bf16，3 seed 均值 | 2.075373 | +0.004290 |

**解读**：

- **同 seed 差异仅 0.0017（< 1σ）** → GPU/bf16 相对 CPU/fp32 未造成可测的系统性损失，
  `research.md` R6 的担忧（bf16 对小模型掉精度）在此规模下**不成立**。
- 均值差 0.0043 主要来自 seed 差异，而非环境差异——因为 GPU 的 3 个 seed 覆盖了
  2.0728～2.0778 的范围，而 CPU 只有一个 seed 落在该范围下端。

**结论（R6 收尾）**：后续候选统一使用 **GPU + bf16** 训练，基线与候选同环境同精度，
对照成立。评估仍按官方口径用 **CPU + fp32**，该差异已验证可复现（见 PHR-007）。

## R9. 阶段 B 筛选结果：主机制假设未获支持（2026-09-19）

**测量条件**：各候选 `--implementation student`，GPU + bf16，seed 17，1200 步 = 9,830,400 targets。
对照为 `base-s17`（同 seed、同环境、同精度）。门槛 = 0.005028 BPB（R8）。

| 候选 | 参数量 | 验证 BPB | 与 base-s17 之差 | 与基线均值之差 | 相对 |
|---|---:|---:|---:|---:|---:|
| **BASE** (d128 L4 MHA) | 1,088,256 | **2.072792** | — | — | — |
| C1 (d128 L4 MQA) | 989,184 | 2.079097 | +0.006305 | +0.003724 | +0.18% |
| C6 (d120 L5 MQA) | 1,039,620 | 2.105199 | +0.032407 | +0.029826 | +1.44% |
| C3 (d112 L6 MQA) | 1,056,272 | 2.111076 | +0.038284 | +0.035703 | +1.72% |
| C4 (d112 L6 MHA) | 1,170,176 | 2.112802 | +0.040010 | +0.037429 | +1.80% |
| C5 (d96 L8 MQA) | 1,004,352 | 2.166496 | +0.093704 | +0.091123 | +4.39% |

### 结论 1：全部候选劣于基线，且呈单调趋势

沿等参数前沿（参数量均落在基线 ±8% 内）：

```
宽度 越大 / 层数 越少   →   越好
(128, L4) 2.0728  <  (120, L5) 2.1052  <  (112, L6) 2.1111  <  (96, L8) 2.1665
```

每一档的差值都**远超** 0.0050 的门槛（除 120→112 档为 +0.0059，略高于门槛）。
**结果与主机制假设方向完全相反**：原假设是"省下 KV 参数换取更多层数会更好"，实测是
"层数增加、宽度收窄 → 明确变差"。

### 结论 2：KV 共享（MQA）本身是中性的

| 对比 | 差值 | 判定 |
|---|---:|---|
| C3 (MQA) vs C4 (MHA)，`d=112, L=6` 不变 | **−0.001726** | 远小于门槛 → **无差异** |
| C1 (MQA) vs BASE (MHA)，`d=128, L=4` 不变 | +0.003724（vs 均值） | 小于门槛 → **无差异** |

这是本次筛选最重要的副产品：**MQA 既没帮忙也没伤害**。因此 5 个候选的差异**完全由
`(宽度, 层数)` 的分配决定**，与注意力类型无关。T022 的机制陈述改写据此进行。

### 结论 3：可能的机制解释（待验证，非结论）

本项目使用**权重绑定的输出投影**（`head.weight = token.weight`），因此输出层的秩上限为 `d`。
收窄 `d` 会同时压缩输出表达能力。这为"宽度比深度重要"提供了候选解释，
也解释了为何收窄带来的损失格外大。此解释**尚未验证**，需由 R9 后续实验区分：
若"宽度效应"由绑定投影的秩约束主导，则在同等参数下继续加宽应当持续获益。

### 后续方向：沿前沿反向搜索

既然趋势指向"更宽更浅"，则应在**同参数预算**下向反方向搜索。已按 R2 公式核算候选：

| ID | 配置 | 参数量 | 相对基线 | 投影+MLP | 注意力核 | 每 token MACs | 相对基线 |
|---|---|---:|---:|---:|---:|---:|---:|
| W1 | d=144, L=3, MHA | **1,084,176** | −0.37% | 746,496 | 221,184 | **967,680** | **−7.71%** |
| W2 | d=168, L=2, MHA | **1,069,152** | −1.76% | 677,376 | 172,032 | **849,408** | **−18.99%** |
| W3 | d=152, L=3, MQA | **1,083,532** | −0.43% | 727,776 | 233,472 | **961,248** | **−8.33%** |

（MACs 按 R2 的三段式模型核算：`投影+MLP = L·(attn_proj + 8d²)`，`注意力核 = L·2·T·d`，`T = 256`。
早期草稿中此列曾填错，已按公式重算。）

**需要注意的边界情况**：到 `L=3` 时参数量预算已基本被宽度吃满（`d=144` 即为 −0.37%）；
继续加宽必须继续减层，`L=2` 时可到 `d=168`。`L=1` 时 `d≈184`（+2.6%）但仅单层注意力，
表达能力可能不足。因此本方向的搜索空间很窄，且**前沿极大值有可能就在基线附近**
（即 `(128, 4)` 已接近该前沿最优）——若如此，则架构方向无收益，应转向训练侧（阶段 F）。

### 结论：层数在等参数前沿上单调有害

把参数量固定在基线 ±3% 内，只沿前沿移动 (宽度, 层数)：

```
层数 4 → 2.0728    层数 2 → 1.9984
层数 3 → 2.0416    层数 1 → 1.9431   ← 单调下降
```

**每一档都远超 0.0050 门槛**，且趋势严格单调。最优配置是**单层 + 宽度 224**，
相对基线改进 **6.26%**，同时**计算量比基线少约 34%**（见下）。

### 可靠性验证

1. **参数核算一致**：全部 12 个配置的实现参数量与 R2 公式预测逐位吻合。
2. **跨环境复核**：W5 的验证 BPB 在 `gpt` 环境 CPU FP32 下复算得
   `1.9595546471684466`，与 GPU 报告的 `1.9595546503753785` 相差 **3e-9**，
   排除训练环境或精度造成的假象。
3. **幅度远超噪声**：最小改进 −1.51%，是门槛（0.24%）的 6 倍以上。

### 计算量对比（R2 三段式模型）

| 配置 | 投影+MLP | 注意力核 | 每 token MACs | 相对基线 |
|---|---:|---:|---:|---:|
| BASE (128, L4) | 786,432 | 262,144 | 1,048,576 | 0% |
| W5 (220, L1) | 580,800 | 112,640 | **693,440** | **−33.9%** |
| **W7 (224, L1)** | **602,112** | **114,688** | **716,800** | **−31.6%** |

> **⚠️ 修正记录（2026-09-21）**：本节早期版本把 W5（`d=220`）的 MACs 误填在 W7 行，
> 并据此把 W5 的 −33.9% 当作 W7 的数字传播到 plan.md 与 PHR-011。核对时按 R2 三段式
> 模型重算 W7（`d=224`）得 `4·224² + 8·224² = 602,112`、`2·256·224 = 114,688`，
> 合计 **716,800（−31.6%）**。W5 的 −33.9% 本身无误，仅条目错位。
> 结论方向不变：W7 仍在计算量上优于基线。

即最优配置**同时**在参数量（+3.06%）、预测质量（−6.26%）和计算量（−31.6%）上占优，
不存在预测质量与计算成本的权衡取舍——这一点对报告的"批判性分析"章节很重要。

### 可能的机制解释（需进一步区分）

1. **优化难度**：固定 1200 步与固定 LR 调度下，深层模型可能更难优化。趋势的严格单调性
   支持"深度带来的优化困难超过了其表达收益"。
2. **绑定投影的秩约束**：本项目共享 `head.weight = token.weight`，输出分布秩上限为 `d`。
   宽度 224 意味着输出秩 224，而基线仅 128。这可能解释了为何加宽收益如此巨大。
   **注意**：加宽同时提高了绑定 embedding 的参数量占比（W7 中 embedding 占
   458,752/1,121,568 = 40.9%，基线为 24.1%）。
3. **数据规模**：仅 9,830,400 个训练目标（约 2.74 epoch），浅层模型的有效容量可能本就更匹配。

**待区分的对照**：若主要源于解释 2，则"解绑输出投影"应在窄模型上带来类似收益；
若源于解释 1，则给深层模型更多训练步数应当缩小差距。两者均未验证。

### 对计划的影响

这是机制陈述的**第二次改写**（首次为 MQA 中性，见 R9）。原机制"MQA 换深度"已被
两轮实验否定，新机制为"等参数下把容量分配给宽度、避免深度"。可消融的对比即上表的
等参数前沿本身（(224,1) vs (128,4) vs 中间各档），证据强度高于原设计。

## R12. 训练目标数依赖：机制结论在一个更长训练的机制上被反转（2026-09-21）

### 背景与动机

R10 的等参数前沿**全部**在 9,830,400 targets（2.72 epochs，8.8 tokens/param）下测得，
由此得出"宽度支配深度"。R11 的"验证集与测试集改进幅度一致"只能说明改进**不是划分特异的**
——验证集与测试集都在**同一个训练预算**下，因此该证据**不能**支撑机制与训练预算无关。
R10 曾把"数据规模"列为三个未被区分的解释之一，并明确写出区分实验"给深模型更多步数"
**尚未执行**。本节执行该实验。

### 预登记判定规则（在跑之前确定，未事后修改）

- 门槛沿用 **0.0050 BPB**（R8 的 2σ 门）
- 只用验证集选择；测试集在冻结前不动
- **停止规则**：当某点最后 1,200 步的验证改善低于 0.001 时停止外推

### 实验 1：同配置、只改步数

条件：seed 17、bf16、同一 GPU、同一数据、cosine 调度随 `--steps` 整体拉长
（即"同调度形状、更多目标数"），其余全部不变。

| 步数 | 已处理目标数 | epochs | tokens/参数 | W7 (d224 L1) | BASE (d128 L4) | W7−BASE | 门槛倍数 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 1,200 | 9,830,400 | 2.72 | 8.8 | 1.943094 | 2.072792 | **−0.129698** | −25.9 |
| 2,400 | 19,660,800 | 5.44 | 17.5 | 1.806035 | 1.881351 | −0.075316 | −15.1 |
| 3,600 | 29,491,200 | 8.16 | 26.3 | 1.764189 | 1.795245 | −0.031056 | −6.2 |
| 4,800 | 39,321,600 | 10.88 | 35.1 | 1.742466 | 1.752345 | −0.009879 | −2.0 |
| 6,000 | 49,152,000 | 13.60 | 43.8 | 1.727835 | 1.726357 | +0.001479 | +0.3 |
| 12,000 | 98,304,000 | 27.21 | 87.6 | 1.715212 | **1.684559** | **+0.030654** | **+6.1** |

两点观察：

1. **训练量本身是远大于架构的杠杆**。W7 仅靠训到 12,000 步就从 1.943094 降到 1.715212
   （改善 **0.227882**）；而架构改写在 1,200 步下的贡献是 0.129698。GUIDE 第 3 节明确
   "Training duration and architectures are unrestricted within the evaluation limits"，
   即训练时长不受评估预算限制——这是一个此前完全未开采的自由度。
2. **W7 相对基线的优势单调衰减并反转**。线性插值得过零点在 **5,844 步**
   （47,872,055 targets，13.2 epochs）：低于该预算宽度更好，高于该预算深度更好。
   6,000 步处的 +0.001479 小于 seed σ=0.002514，应读作**打平**而非反超；
   12,000 步处的 +0.030654 是门槛的 6.1 倍，属**确认的反转**。

### 实验 2：在饱和步数（12,000）重跑等参数深度阶梯

为与 1,200 步前沿**严格同构**（只改训练目标数，不改任何其他变量），阶梯点必须同时满足
"参数量在基线 ±3% 内"与"多层注意力（MHA）"。原 `c6/c3/c5` 是 MQA（`kv_heads=1`），
直接复用会把已被判为中性的 MQA 混入阶梯，因此按 R1 公式新建 4 个 MHA 配置
（`mhal5..8`，宽度取使总参数落在 ±3% 内的最大 4 的倍数），并纳入
`tests/test_equivalence.py` 的可执行参数量核对（现 14/14 通过）。

| 层数 | 宽度 | 参数量 | vs 基线 | 每 token MACs | vs 基线 | 验证 BPB | 距最优 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 1 | 224 | 1,121,568 | +3.06% | 716,800 | −31.64% | 1.715212 | +0.039020 |
| 2 | 168 | 1,069,152 | −1.76% | 849,408 | −18.99% | 1.679032 | +0.002839 |
| **3** | **144** | **1,084,176** | **−0.37%** | **967,680** | **−7.71%** | **1.676193** | **最优** |
| 4 | 128 | 1,088,256 | 0.00% | 1,048,576 | 0.00% | 1.684559 | +0.008366 |
| 5 | 116 | 1,082,396 | −0.54% | 1,104,320 | +5.32% | 1.690292 | +0.014099 |
| 6 | 108 | 1,097,280 | +0.83% | 1,171,584 | +11.73% | 1.684304 | +0.008111 |
| 7 | 100 | 1,079,700 | −0.79% | 1,198,400 | +14.29% | 1.701458 | +0.025265 |
| 8 | 96 | 1,116,096 | +2.56% | 1,277,952 | +21.88% | 1.697476 | +0.021283 |

**结论 1：最优深度随训练目标数上移。**

| 训练目标数 | 阶梯内最优 | 阶梯内最差 | 宽度/深度偏好 |
|---|---|---|---|
| 9,830,400（1,200 步） | L1（浅端，d=224） | L4（深端，d=128） | 越浅越好，单一调 |
| 98,304,000（12,000 步） | **L3（中段，d=144）** | **L1（浅端，d=224）** | 内部最优点，浅端反而最差 |

即：**宽度与深度的最优分配不是常数，而是训练目标数的函数**；训练量越大，
最优配置越向深度方向移动。L3 相对 L1 的优势为 0.039020（门槛的 7.8 倍），
相对 L4 为 0.008366（1.67 倍）。L2 与 L3 之间为 0.002839，**在噪声带内**，
故二者统计上打平，最终择一需多种子复现（见下）。

### 对 R10 三个未区分解释的判定

R10 列出三个候选解释。实验 1 的结果与其中两个的预测方向一致：

| R10 中的解释 | 该解释的预测 | 实测结果 | 判定 |
|---|---|---|---|
| 1. 固定步数预算下深度更难优化 | 给深模型更多步数，差距应缩小 | 差距确实缩小并反转 | **获得支持** |
| 3. 数据规模（9.83M targets 下浅宽更匹配语料） | 训练量变化应改变结论 | 结论确实随训练量反转 | **获得支持** |
| 2. 绑定输出投射的秩约束（rank ≤ d） | 需解绑实验才能区分 | **未执行** | 仍未区分 |

因此"宽度支配深度"**不是架构的固有性质**，而是**训练目标数预算的函数**。
原报告 §6.2 把"给深模型更多步数"列为未执行的区分实验；该实验现已执行，
且其结果否定了把该效应当作普遍架构规律的表述。

### 诚实记录：对既有成功标准适用范围的影响

- **SC-002 / SC-003 的表述本身已限定机制**（SC-002 明确写 "9,830,400"），在该机制下
  L3-d144 对基线为 2.041589 vs 2.072792，改善 0.031203 ≥ 0.01 → **仍成立**。
- 但在最终提交所用的 12,000 步机制下，回退到基线式"深而窄"分配**反而更好**
  （L3 → L4 为 1.676193 → 1.684559）。该门槛**未被事后修改**，而是如实记录：
  SC-003 的适用范围是 9.83M-targets 机制，**不**外推到 98.3M-targets 机制。
- 命令行接口、数据与评测协议全程未改动；`check_integrity.py` 的 13 个协议文件保持匹配。
  本会话唯一被改动的协议外文件是 `code/train.py`（新增 `--weight-decay-1d` 与
  `--ema-decay` 两个开关，**默认值与改动前逐位等价**，已由 `w7-s17-r1200-ctrl2`
  对照运行验证：1.943105 vs 1.943087，差 1.8e-05）。

### 实验 3：种子复现与最终选型

阶梯最好的两点（L3 d144 = 1.676193、L2 d168 = 1.679032）只差 0.002839，在噪声带内。
按 R8 的方法学做三 seed 复现：

| 配置 | seed 17 | seed 42 | seed 123 | 均值 | σ | 参数量 | MACs/token |
|---|---:|---:|---:|---:|---:|---:|---:|
| L3 (d144, L=3) | 1.676193 | 1.675741 | 1.689320 | 1.680418 | 0.007712 | 1,084,176 | 967,680 |
| **L2 (d168, L=2)** | 1.679032 | 1.670718 | 1.669866 | **1.673206** | 0.005064 | **1,069,152** | **849,408** |

**单 seed 的排名没有复现**：复现后名义最优由 L3 移到 L2。均值差 0.007212，差值标准误
0.005327，**t = 1.35，不显著**。必须强调：R8 的 0.0050 门槛是为**单 seed 差值**标定的，
不能直接套用到**均值差**上而不计标准误——直接套用会得出"L2 confirmed better"的错误结论。
两点在质量上不可区分，故改按**成本**选型：L2 比 L3 少 15,024 个参数、每 token 少 118,272 MACs，
两个轴都不劣。冻结 checkpoint 取**预登记的 seed 17**（而非三 seed 中验证最优的
seed 123 = 1.669866），以免 seed 挑选进入记录分。

### 噪声底是机制相关的（必须记录的弱点）

本机制下实测 seed σ 为 0.005064（L2）与 0.007712（L3），是 R8 在 **1,200 步**实测的
0.002514 的 2–3 倍。把在一个机制下标定的门槛套到另一个机制上，是本项目的一处真实弱点，
且方向双向：它既让 L2/L3 的单 seed 比较显得决定性，也让 6,000 步处的打平（+0.001479）
承担被误读成"反转"的风险。因此报告 §4.4 改为报告**差值标准误**，而不是把点估计直接对门槛比较。
