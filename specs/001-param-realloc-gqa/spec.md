# Feature Specification: 参数重分配与分组查询注意力改进（MP1 BPB 优化）

**Feature Branch**: `001-param-realloc-gqa`
**Created**: 2026-09-19
**Status**: Draft
**Input**: 用户需求 —「开始设计 MP1 改进方案，但是我必须知道每一步都干了什么」

---

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 同 token 预算下的公平改进证据 (Priority: P1)

作为**论文作者（学生本人）**，我需要在**与基线完全相同的已处理训练目标数**条件下，证明改进后的架构在验证集上优于基线，从而确立"改进来自结构而非更多算力"这一结论。

**Why this priority**: 这是整个作业的科学核心。若缺少这一对照，任何 BPB 提升都可能被归因为"训练更久"，评审可据此否定全部贡献。P1 因为它单独就能构成一个可交付的最小成果（一个有依据的架构结论）。

**Independent Test**: 用相同 seed、相同步数、相同 batch size 训练基线与改进模型各一次，比较 validation BPB。两条曲线可在同一张图上独立呈现并得出结论。

**Acceptance Scenarios**:

1. **Given** 基线配置与固定 seed，**When** 训练 9,830,400 个目标后评估 validation，**Then** 得到可复现的基线 BPB（本机锚点 2.0711）。
2. **Given** 改进配置与同一 seed 与同一目标数，**When** 训练并评估 validation，**Then** 改进配置 BPB 严格低于基线。
3. **Given** 两套配置，**When** 对比参数量，**Then** 二者参数量差异在 ±3% 以内（排除"单纯变大"的解释）。

### User Story 2 - 关键机制的消融证据 (Priority: P1)

作为**论文作者**，我需要在**参数量与训练目标数都固定的等参数前沿上移动容量分配**（在宽度与深度之间），测量这一分配决策单独的贡献，从而论证改进的因果来源。

> **机制修订说明（2026-09-19，第二次改写）**：本故事的原始表述以"分组查询注意力（MQA）"
> 为关键机制（"用 KV 共享省下参数换取更多层数"）。阶段 B 实测否定了该假设：MQA 本身
> 对 BPB 中性（见 research.md R9），且沿等参数前沿加深反而单调变差。反向搜索后发现
> **宽度支配深度**（R10）。关键机制据此改写为"等参数下把容量分配给宽度、避免深度"。
> 被否定的初版机制与其否定证据必须一并纳入报告（见下方验收场景 4）。

> **机制修订说明（2026-09-21，第三次改写——限定适用范围）**：第二次改写给出的
> "宽度支配深度"是在**单一训练目标数预算**（9,830,400）下测得的。R12 执行了 R10 中
> 标注为"未执行"的区分实验（给深模型更多步数），结果：W7 相对基线的优势随训练量
> 单调衰减，并在约 **5,844 步（47.87M targets）**处反转；在 12,000 步（98.30M targets）
> 下，等参数深度阶梯的**最优点移到 L3（d=144）**，而 W7（L1）成为最差点。
> 因此"宽度支配深度"的准确表述是**训练目标数预算的函数**，而非架构的固有性质。
> **本次改写不修改任何既有成功标准**：SC-002 已明确限定在 9,830,400 targets，在该机制下
> 依旧成立；SC-003 同样仅在 9.83M-targets 机制下成立，其在 98.3M-targets 机制下
> **不成立**——这一点必须如实写入报告，不得通过事后放宽或重定义门槛来掩盖。
> 详见 research.md R12。

**Why this priority**: 作业明确要求"an ablation of your key mechanism"。且消融是与 User Story 1 并列的独立证据链——它回答"为什么有效"，而 US1 只回答"是否有效"。同为 P1。

**Independent Test**: 在参数量处于基线 ±3% 内、token 预算完全相同、seed 相同的条件下，比较若干 (宽度, 层数) 配置的 validation BPB，检验序列是否单调且每一档都超过噪声门槛。

**Acceptance Scenarios**:

1. **Given** 改进架构的最终配置（单层、宽 224），**When** 沿等参数前沿再取若干中间配置（如 (144, 3)、(168, 2)、(220, 1)），**Then** 得到一条单调的 BPB 序列。
2. **Given** 该序列，**When** 与基线 (128, 4) 比较，**Then** 最优配置的改进幅度 ≥ 0.01，且每一档的差异均超过噪声门槛。
3. **Given** 前沿对比，**When** 检查参数量、token 预算与 seed，**Then** 各点参数量均落在基线 ±3% 内，已处理训练目标数完全相等，seed 相同。
4. **Given** 关键机制已被改写两次，**When** 撰写报告，**Then** 必须同时披露两版被否定的机制（"MQA 换深度"与"MHA 下加深"）及其否定证据，不得只呈现最终成立的方向。

### User Story 3 - 预算合规且可复现的交付物 (Priority: P2)

作为**同行评审者**，我需要获得不可变代码与匹配的 checkpoint bundle，在**不重新训练**的前提下、在规定的评估预算内（CPU 时间 ≤5× 基线、峰值内存 ≤4 GiB、推理资产 ≤64 MiB），用 FP32 在 CPU 上复现作者报告的分数。

**Why this priority**: 这是成绩被承认的前提条件——分数无法复现则不计入排名，且公开评审阶段可被举报。P2 因为 P1 的两项证据即使完整，缺少合规交付物也无法获得分数。

**Independent Test**: 在一台干净机器上按作者给出的安装与评估指令操作，比较复现 BPB 与报告值。

**Acceptance Scenarios**:

1. **Given** checkpoint bundle 与评估指令，**When** 评审者执行 FP32 CPU 打分，**Then** 复现 BPB 与报告值的差异 < 1e-3。
2. **Given** 冻结的预测器，**When** 测量打分耗时、峰值内存与推理资产体积，**Then** 三项分别 ≤ 5× 基线、≤ 4 GiB、≤ 64 MiB。
3. **Given** 评估流程，**When** 评审者重建预测器，**Then** 无需任何训练步骤、无需网络访问即可完成。

### User Story 4 - 完整的方法与成本披露 (Priority: P3)

作为**课程教师 / 自动化核查脚本**，我需要一份 ≤10 页的报告与运行记录，其中包含基线、同 token 对照、消融三项实验，以及训练与搜索成本的完整披露，从而判断结果真实且方法可理解。

**Why this priority**: 影响最终评级与创新性评价，但不影响分数本身能否复现。P3 因为它是 P1/P2 结果的呈现层，可在证据齐备后补齐。

**Independent Test**: 依据报告与运行记录，第三方能够重建方法描述、核对所有实验数字、并追踪每个 checkpoint 的来源。

**Acceptance Scenarios**:

1. **Given** 全部实验完成，**When** 提交报告，**Then** 报告 ≤10 页并覆盖方法、对比、消融、批判性分析四个部分。
2. **Given** 运行记录，**When** 核查任一项报告数字，**Then** 可定位到对应的 run 目录产物。
3. **Given** 最终 checkpoint，**When** 追溯其来源，**Then** 可查到训练步数、seed、已处理目标数与搜索成本。

### Edge Cases

- **短训练筛选的排名不可迁移**：在小步数（约 300–400 步）筛选中胜出的配置，在完整训练步数下可能改变名次，尤其在结构与学习率存在交互时。缓解：筛选结论必须经过一次完整步数复核后才可作为最终选择。
- **契约测试被静默破坏**：改动注意力投影或归一化后，`predict_log_probs` 可能不再满足归一化或状态重置要求，导致打分器直接抛错。缓解：每次结构改动后必须重跑全部契约测试。
- **checkpoint 跨环境不可加载**：若训练环境与官方评估环境的数值库版本不同，可能出现加载失败或数值偏差。现状：已实测跨版本可加载，复现差异约 8.6e-9。
- **推理资产超出 64 MiB**：若保存多份权重快照（如多个训练阶段的平均候选）会超出上限。缓解：仅落盘单一最终权重文件。
- **打分时间超出 5× 上限**：加深网络会提高单次打分耗时。缓解：每轮结构改动后实测完整测试集打分时间，上限按基线折算。
- **测试集污染**：使用测试集做任何选择即违反规则且方法不再可冻结。缓解：所有选择只在验证集上进行，测试集仅在方法冻结后运行。
- **可复现性漂移**：采样与权重平均若未固定随机源，重跑分数会漂移。缓解：固定 seed 并在提交中给出精确命令。
- **验证集过拟合**：反复在验证集上挑选配置会使其失去选择效力。缓解：限制筛选候选数，并保留一次最终确认性评估。

## Requirements *(mandatory)*

### Functional Requirements

**模型接口与契约**

- **FR-001**: 模型 MUST 保持上下文长度 256 与词表规模 2048，且不得修改评测协议定义。
- **FR-002**: 模型 MUST 同时提供两个接口：训练用未归一化 logits 与评估用归一化自然对数概率，输出形状均为 `[batch, time, 2048]`。
- **FR-003**: 位置 t 的预测 MUST 只依赖该序列中 t 及之前的输入，不得访问任何后续 token。
- **FR-004**: 每次评估调用 MUST 重置全部临时状态；独立窗口、样本与打分轮次之间 MUST 不传递状态。
- **FR-005**: 评估接口 MUST 返回全部有限且已归一化的对数概率（各行对数和为 0，误差 < 1e-3）。
- **FR-006**: 模型 MUST 通过全部 5 项契约测试（因果性、归一化与样本独立、窗口间状态重置、梯度存在且有限、目标计数不重不漏）。
- **FR-007**: checkpoint MUST 记录实现模块名与完整配置，且提交包 MUST 包含重建预测器所需的全部资产，使评估方无需重新训练即可复现。

**数据与因果纪律**

- **FR-008**: 训练 MUST 只使用提供的训练文本；数据文件、分词器与评估器 MUST 保持不变。
- **FR-009**: 所有超参与结构选择 MUST 在验证集上完成；测试集 MUST 仅在方法冻结后运行。
- **FR-010**: 方法 MUST 在测试前冻结；冻结后同一预测器可重复评估用于计时或复现。
- **FR-011**: 权重、统计量与任何检索条目 MUST 仅派生自训练文本，不得缓存验证集或测试集的答案。

**资源预算**

- **FR-012**: 冻结预测器的 CPU 打分时间 MUST ≤ 基线的 5 倍。
- **FR-013**: 峰值评估内存 MUST ≤ 4 GiB。
- **FR-014**: 未压缩推理资产 MUST ≤ 64 MiB。

**实验证据与披露**

- **FR-015**: 交付物 MUST 包含三项实验证据：初始基线、相同已处理训练目标数下的对照、以及关键机制的消融。
- **FR-016**: 交付物 MUST 披露训练与搜索成本，包括所有 seed、已处理训练目标数、checkpoint 沿革与搜索开销。
- **FR-017**: 交付物 MUST 包含一份不超过 10 页的报告，覆盖方法、对比、消融与批判性分析（含预测质量与计算成本的权衡）。
- **FR-018**: 交付物 MUST 包含不可变代码仓库与精确的安装、训练、评估指令。

### Key Entities

- **模型配置**：定义结构的参数集合（词表、宽度、头数、层数、上下文、注意力投影方式）；是区分基线与改进版本的唯一标识，随 checkpoint 一同记录。
- **Checkpoint**：一次训练的产物，包含协议标识、实现模块名、配置、权重与 seed；是评估方重建预测器的唯一入口。
- **运行记录**：一次训练的完整度量，包括已处理目标数、耗时、损失曲线、验证 BPB 与产物哈希；是成本披露与数字核对的数据源。
- **实验单元**：一次受控比较（基线 / 同 token 对照 / 消融），由固定 seed、固定目标数与单一变量差异定义。
- **基线锚点**：作为所有对比参照的冻结测量值，必须在本机重新测得而非引用他人数值。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 最终预测器的完整测试集 BPB 不高于 2.038（相对本机基线 2.1013 改进 ≥3%）。
  **门槛保持原值不变**：该门槛在机制改写前后一律留用，既不因现已达标而事后收紧（移动球门），也不放宽。实际达成幅度在报告中单独报告。
- **SC-002**: 在已处理训练目标数相同（9,830,400）且参数总量差异 ≤3% 的条件下，改进配置的验证集 BPB 严格低于基线。
- **SC-003**: 在等参数前沿上回退关键机制（即回到基线式的"深而窄"容量分配）后，验证集 BPB 变差 ≥ 0.01。
  **实测**：最优 (224, 1) = 1.9431 对基线 (128, 4) = 2.0728，差 **0.1297**，为门槛的 13 倍。
- **SC-004**: 冻结预测器的完整测试集 FP32 CPU 打分时间 ≤ 60 秒（本机基线 11.86 秒的 5 倍）。
- **SC-005**: 评估流程峰值内存 ≤ 4 GiB。
- **SC-006**: 未压缩推理资产总体积 ≤ 64 MiB。
- **SC-007**: 5 项契约测试全部通过。
- **SC-008**: 使用提交中的精确命令重跑，测试集 BPB 与报告值的差异 < 1e-3。
- **SC-009**: 第三方仅凭 checkpoint bundle 与评估指令即可复现分数，全程无需训练步骤与网络访问。
- **SC-010**: 报告页数 ≤ 10 页，且三项实验证据齐备。

## Assumptions & Dependencies

**已确认的环境事实（本机实测）**

- 官方评估环境：conda 环境 `gpt`，Python 3.12.14 + torch 2.7.1+cpu + numpy 2.5.3 + tokenizers 0.21.4；契约测试 5/5 通过。
- 训练加速环境：conda 环境 `pytorch`，Python 3.10 + torch 2.8.0+cu128，CUDA 可用（RTX 3060 Laptop 6 GB）。
- 跨环境可移植性已验证：GPU 训练产出的 checkpoint 在 `gpt` 环境 CPU FP32 下加载成功，验证 BPB 差异约 8.6e-9。
- 基线锚点（本机，4 线程，seed 17，1200 步）：测试 BPB 2.1013、验证 BPB 2.0711、训练 667.6 秒、测试打分 11.86 秒、峰值内存 1.56 GiB、checkpoint 4.17 MiB。
- 训练吞吐：GPU 约 29× 于 CPU 4 线程；数据加载约 20 秒为每次运行的固定开销。

**假设**

- 基线诊断结论成立：训练损失与验证损失差距仅 0.059 nats（1.4%），已处理目标数约为训练集规模的 2.74 倍，每参数约 9.03 个 token —— 处于欠拟合/算力受限区间，因此增加正则化预计无益。
- 项目根目录当前**不是 git 仓库**，也没有 `.specify/`。本规格及其配套产物由 agent 直接创建于项目根目录；最终提交所需的不可变 GitHub 仓库需在提交阶段另行建立。
- 训练时长与架构不受限制，但必须在报告中披露成本；评估预算独立于训练预算。
- **命名沿革**：特性目录与分支名 `001-param-realloc-gqa` 中的 `gqa` 反映**初版**机制
  （分组查询注意力）。该机制已被实测否定（MQA 对 BPB 中性，见 research.md R9），
  最终模型使用标准多头注意力。目录名保留不改，以避免大量交叉引用失效；
  报告与提交文档中 MUST 使用修订后的机制表述，不得沿用 `gqa` 作为机制名。
- 报告语言已确认：**英文**（2026-09-19 决策）。依据：GUIDE 与 code/README 均为英文，课程为英文授课，同行评审者可能非中文使用者。报告、代码注释与提交文档一律使用英文；与作者的过程交流仍用中文。

**依赖**

- 作业提供的固定评测协议与评估器、固定分词器与数据文件（均不可修改）。
- 可用的 GPU 训练环境与 CPU 评估环境（已就绪）。
- 课程网站提交入口与 GitHub issue 流程（提交阶段使用）。
